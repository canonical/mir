# Mir 2.31

(release-2.31.0)=

Release Candidate

## What's new in [Mir 2.31.0](https://github.com/canonical/mir/releases/v2.31.0)

### Freely positioned magnifier

The magnifier can now be positioned independently of the pointer, making it useful on touch devices and other cursorless systems. On-screen controls let users move and resize the magnified area and adjust its zoom with a pointer or one touch contact. Compositor authors can select this behavior with `miral::Magnifier::set_behavior()` or the `{magnifier, behavior}` live configuration option. See {ref}`mir-accessibility-methods` ([#5135](https://github.com/canonical/mir/pull/5135), [#5207](https://github.com/canonical/mir/pull/5207)).

### Display configuration and presentation APIs

MirAL now provides `OutputConfiguration` strategies for customizing output settings before they are applied and observing the configuration afterward ([#5224](https://github.com/canonical/mir/pull/5224)). Display platform authors can also use the presentation-planning interface to describe which renderables can be placed directly on hardware planes and which need composition. Mir retries presentation after a failure rather than waiting for new client damage ([#5290](https://github.com/canonical/mir/pull/5290), [#5336](https://github.com/canonical/mir/pull/5336)).

### Wayland protocol support

Mir adds experimental support for `ext_foreign_buffer_v1`, allowing a client to attach an opaque buffer whose contents are maintained by the compositor from an image-capture source. Availability depends on the compositor's policy and the supported image-capture source ([#5203](https://github.com/canonical/mir/pull/5203), [#5274](https://github.com/canonical/mir/pull/5274)).

The unstable `xdg-decoration` protocol is now version 2. Clients can negotiate decoration mode throughout a toplevel's lifetime, including after attaching a buffer ([#5239](https://github.com/canonical/mir/pull/5239)).

The experimental `mir_shell_v1` protocol is now version 2, allowing clients to transition a managed surface between archetypes when the compositor permits it ([#5343](https://github.com/canonical/mir/pull/5343)).

## Minor features

### Rendering and display

Mir can select a blitter renderer when it fully supports an output and the available GL renderer has impaired performance. This provides another hardware-accelerated rendering path for platforms with blit or composition hardware ([#5213](https://github.com/canonical/mir/pull/5213), [#5293](https://github.com/canonical/mir/pull/5293), [#5328](https://github.com/canonical/mir/pull/5328), [#5317](https://github.com/canonical/mir/pull/5317)).

The output configuration API now confirms when a changed configuration has been applied ([#5259](https://github.com/canonical/mir/pull/5259), [#5321](https://github.com/canonical/mir/pull/5321)). `DisplayInfo` also exposes the physical address read from an output's EDID ([#5291](https://github.com/canonical/mir/pull/5291)).

### Input and application authorization

Touch input now accounts for output transformations and scaling ([#5292](https://github.com/canonical/mir/pull/5292)), and touchpads can use libinput's circular scrolling mode ([#5246](https://github.com/canonical/mir/pull/5246)). Input triggers also avoid aggressively filtering key bindings ([#5249](https://github.com/canonical/mir/pull/5249)).

MirAL application authorizers can inspect client AppArmor, Snap and Flatpak metadata when restricting access to Wayland extensions. Sandbox metadata should be used to restrict permissions, not to grant additional privileges ([#5209](https://github.com/canonical/mir/pull/5209)).

### Window management

Fullscreen bypass is disabled when output filters or transformations require compositing ([#5310](https://github.com/canonical/mir/pull/5310)), and the MirAL splash screen now fades smoothly ([#5297](https://github.com/canonical/mir/pull/5297)).
